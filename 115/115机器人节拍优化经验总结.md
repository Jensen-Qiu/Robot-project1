# 115 机器人 QJX 产线节拍优化 —— 经验总结

> 对象：115 机器人（10.20.17.115）QJX 产线循环（上料机取料 → 弯曲机放料 → 弯曲机取料 → 下料机放料）
> 主程序：`/data/wxf0721/runtime/programs/all_machin_plc_vision_loop_onestep.py`
> 服务端：`/data/wxf0721/services/`（commands.py / joints.py / main.py / common.py）
> 记录时间：2026-10-29（含 10-28 节拍优化 + 10-29 放料质量修复）
> **成果：机器人净耗时从 ~92s/轮 降到 ~59-61s/轮，降幅约 35%，达成 60s 目标；并解决 WF/XL 放料翻转、挂挡板、误回退等质量问题。**

---

## 一、总览：优化了多少

**衡量口径**：用"机器人净耗时"（= 整轮墙钟总时长 − PLC 等待时间）。PLC 等待是机器人干等总控信号的时间，波动大且机器人无法控制，必须剔除，否则会被它干扰判断。

| 阶段 | 机器人净耗时 | 关键改动 |
|------|:---:|------|
| **优化前基线** | **~92s** | — |
| 并行/合并 + 停稳 | ~70s | 上料后退+右转合并、XL3/WF3 后退并行、WF 停稳 |
| **视觉常驻化（决定性一刀）** | **~59-61s** | 视觉从每工位重启子进程改为常驻服务，socket 进程内直连 |

**最终实测（8 轮，0.5s 停稳 + 视觉常驻 + v2 记录器）**：净耗时 58.6 / 59.9 / 60.8 / 64.1 / 61.9 / 61.3 / 59.9 / 62.3s，均值约 **61s**，最好 **58.6s**。

> 节拍优化（第一~五节）在 10-28 完成并稳定；10-29 的工作集中在**放料质量**（翻转/挂挡板/误回退），见第六节，对节拍基本无影响。

## 三、底盘与上半身"同时运动"的原理（后续并行优化的基础）

分三层，均有真实代码支撑：

1. **服务端双通道 + 双锁 + 关节独立线程池**（`services/main.py`/`common.py`）：
   - 底盘/动作走 `/humanoid/commands/data`（`commands` 锁，串行）；
   - 上半身关节走 `/humanoid/joints/control`（`joints` 锁 + 线程池），`common._states = {"joints":"idle","commands":"idle"}` 两把独立锁。
   - → 底盘在跑的同时，关节可在另一线程同时跑。

2. **主控异步下发**（`minth.py`）：`GO_NOWAIT/REL_NOWAIT` 只发不等，`WBC` 走关节通道，三明治写法实现并行：
   ```python
   G2.REL_NOWAIT({"x": -0.4})   # (1) 底盘后退：异步发出立即返回
   G2.WBC("XL3")                # (2) 上半身收臂：同时在另一通道跑
   G2.REL_WAIT()                # (3) 回头等 (1) 底盘真正完成后汇合
   ```

3. **按命令计数汇合**（`minth._done_counts`）：`REL_WAIT` 只认 `go_rel` 的 done 计数，`WBC` 的 done 归 `WBC`，并行下互不干扰。

**一句话**：同时运动 = 服务端双通道 + 主控 `REL_NOWAIT/GO_NOWAIT` 异步下发底盘 + 紧跟 `WBC` + `REL_WAIT` 按命令计数汇合。

## 四、节拍优化：做了哪些有效改变 · 为什么 · 前后对比

### 改动 1：上料后退 + 右转 合并为"边退边转"
- **为什么**：原流程上料抓完后，先 `REL(x=-0.4)` 后退、再 `REL(yaw=-90°)` 右转，是两个独立底盘动作，中间多一次停稳+启动开销。
- **怎么做**：合并为一个复合相对运动 `REL_NOWAIT({"x":-0.4, "yaw_rad":-radians(90)})`（边退边转），且与 `WBC("SL3")` 收臂并行。
- **前后**：分开做"后退+右转"≈8s → 合并复合动作约 5s，**省约 2.9s/轮**。

### 改动 2：后退与收臂并行（XL3、WF3）
- **为什么**：下料/弯曲放料完成（空爪）后，底盘后退与手臂收臂本可同时做，原来串行。
- **怎么做**：`REL_NOWAIT(后退) -> WBC(收臂) -> REL_WAIT()` 三明治并行。
- **前后**：后退(~2.5s) 被藏进收臂(~1.4s)后面，**各省约 1.5s**。

### 改动 3：弯曲机放料后退距离 400mm -> 200mm
- **为什么**：弯曲机前放完料只需退够安全距离即可，400mm 偏大。
- **怎么做**：WF 段 `REL_NOWAIT({"x": -0.2})`（仅此一处，WQ/XL 仍 400mm）。
- **前后**：后退行程减半，**省约 1s/轮**。

### 改动 4：WF/XL 导航到位后"停稳再伸手"（SETTLE_AFTER_GO_S）
- **为什么**：`GO(2)/GO(3)` 的 done 回执是"导航任务完成"信号，**可能先于底盘物理停稳返回**（底盘仍在沉降/微动）。紧接着 `WBC("WF1"/"XL1")` 就伸手，导致"没到位就往前伸"。
- **怎么做**：在这两段 GO 之后、挂载 WBC 之前加 `time.sleep(SETTLE_AFTER_GO_S)`。初值 1.0s（保守保证到位），现场验证有余量后调小到 **0.5s** 回收节拍。
- **前后**：解决"没到位伸手"问题；0.5s 相比 1.0s 省约 1s/轮（间隙从 ~2.7s 降到 ~1.7s）。
- **注意**：这是"到位准确性"优先于节拍的权衡。若现场又出现伸早，调回 0.8~1.0。

### 改动 5：视觉进程常驻化 + 进程内 socket 直连（**决定性改动，省约 16s/轮**）
- **为什么**：原来主控每个工位(SL1/WF/WQ/XL)都 `subprocess` 启动一次视觉脚本 `vision_align_safe_115.py`，每次重做 GDK 初始化（gdk_init + Robot/TF/Pnc/Camera 构造 + 文件锁 + sleep + 首帧等待 + MQTT 连接）约 2s，4 工位每轮浪费约 8s；再加 python 冷启动 + `source env.sh` 的外壳开销，每次视觉墙钟约 4-6s。
- **怎么做（两步）**：
  1. **常驻服务** `vision_align_server_115.py`：`GDKBackend` + `Minth.G2` 只初始化一次并常驻，监听 Unix socket `/tmp/vision_align_115.sock`，串行处理每次纠偏请求，完全复用原脚本的对位逻辑函数（不改原脚本）。
  2. **主控进程内 socket 直连**（方案A）：主控 `_run_align_onestep` 在 `VISION_USE_SERVER=1` 时直接连 socket 发请求，**不再起客户端子进程**，省掉 python 冷启动 + source env.sh 的外壳开销。服务不可用/异常时自动降级为原 subprocess 直调原脚本（安全兜底）。
  3. **服务端控制模式自愈改进**：原每次请求起一个 `set_control_mode_115.py` 子进程(~2s)，改为进程内用常驻 GDK 直接读 control_mode、仅当 !=1 时才切，毫秒级。
- **前后**：视觉段每轮 **~22s -> ~5.4s**（单次纠偏服务端内部约 1.3s，外壳开销从 ~3.2s 降到几乎为 0）。这是把净耗时从 ~70s 压到 ~60s 的关键一刀。
- **健壮性**：常驻服务用后台守护脚本 `run_vision_align_server_115_daemon.sh`（setsid+nohup）运行，**关终端/断 ssh 不杀服务**；异常退出有 socket 清理；主控侧有降级兜底，服务挂了产线不中断（仅回到原速）。

## 六、放料质量修复（10-29，纠偏/翻转/挂挡板/误回退）

节拍达标后，现场暴露一批**放料质量**问题，逐一定位根因并修复。核心认识：**视觉纠偏的"旋转补偿"和"验证容差"是双刃剑，用错会放偏/翻转/误回退。**

### 6.1 WF 放料翻转 -> 关旋转补偿 + 垂直下放代替 WF2
- **现象**：弯曲机放料时料条翻转，光电检测误判。
- **根因（两层）**：
  1. 原 `WBC("WF2")` 是**关节插值**下压，末端走斜线（实测 WF1->WF2 不仅 Z 降 73.6mm，X 还移 18mm、Y 移 26mm），把料条斜放。
  2. WF 纠偏带**旋转补偿 rry（-2~-4.8度）**，把末端姿态转歪，rry 越大越翻（-4.78度 那轮翻）。WF 的 rotation 读数系**测量偏差非真实姿态偏差**。
- **解法**：
  - **WF 关旋转补偿**（`rot_comp=False`）：只纠平移、姿态保持原始正姿态。
  - **WF2 换成"垂直下放固定落差"**：在纠偏后姿态基础上，用 `OFFSET({"rz": -dz})` 且不带旋转 -> 末端**保持姿态、沿世界 Z 轴垂直直线下降**（EndEffectorController 实测：Z+向上、目标=当前位置加偏移、姿态不变、笛卡尔直线）。消除斜放。
- **不改主程序的接法**：新建 `wf_vertical_place_115.py` + 视觉服务端加 `cmd=drop(station)` + 启动器 patch `G2.WBC`：遇 `"WF2"`->垂直下放、`"XL2"`->垂直下放，其它 WBC 照常；失败自动降级执行原关节动作。主程序源码一字不改。

### 6.2 固定落差 dz 的标定
- **原理**：dz[WF] = Z(WF1末端) - Z(WF2末端)；dz[XL] = Z(XL1末端) - Z(XL2末端)。上/下位姿都是固定关节角，Z 落差为常量，**每工位各标定一次**。
- **标定命令**（会驱动右臂，需无料无遮挡、先停视觉服务、未插充电）：
  ```bash
  python3 wf_vertical_place_115.py calibrate --station WF
  python3 wf_vertical_place_115.py calibrate --station XL
  python3 wf_vertical_place_115.py show        # 查看各工位 dz
  ```
- **闭环下放（重要可靠性修复）**：实测 OFFSET 执行有**系统性欠程**（指令 73.6mm 只走 64-68mm），且偶发 **0mm 漏放**（offset_move 的 done 回执被上一条命令串扰，瞬时返回未真正执行->料条高空坠落）。故服务端改为**闭环**：读 Z -> 发 OFFSET -> 等稳读 Z 验证 -> 不足则补发，最多 3 次，残差 >10mm 判未到位返回 rc=2 降级原关节动作。修复后实降稳定在残差 1-4mm。
- **下放量是纯配置量**（`wf_vertical_place_dz.json`），现场可随时微调、不用重标定、不用重启服务（`load_dz` 每次请求都读文件）。WF 实测从标定值 73.6mm 逐步调到 **66mm**（73.6->70->66，解决"下放过多擦过产品表面"）。

### 6.3 XL 放错/挂左右挡板 -> 同 WF（关旋转+垂直下放）+ 收紧触发容差
- **现象**：下料放料时产品挂在左右挡板上（多次）。
- **根因**：
  1. 同 WF：XL 纠偏带 rry约-3度 旋转转歪 + XL2 关节插值斜放。
  2. **关键**：之前为"减少误回退"把 XL 验证容差放宽到 10mm，而该容差**同时控制"动作前要不要纠偏"的门限**——导致 5-8mm 的 Y(左右)偏差被判"已达标"直接跳过纠偏（net=0），残留 Y 偏差蹭挡板（实测 8 轮里 7 轮 net=0 没纠偏）。
- **解法（方案A）**：XL `rot_comp=False` + XL2 垂直下放 + **xy_tol 收回 4mm** + `one_step_verify=False`。效果：Y 偏差 >4mm 就纠偏对准（消除挂挡板），纠完不回退。
- **关键教训**：`xy_tol` 这一个参数同时控制"动作前门限"（要不要纠）和"动作后验证"（要不要回退）。放宽它会**同时**降低纠偏触发率——这是挂挡板的隐藏根因。

### 6.4 纠偏"成功又回退原位" -> 统一扩大验证容差
- **现象**：SL1/WQ 纠偏显示 rc=2，回退到纠偏前位置，抓/放失败。
- **根因**：`--one-step-verify` 下，纠偏后验证残差超阈值就 `rollback` 撤销 OFFSET 回原位。而残差多为**测量偏差非真实偏差**（SL1 实测 4-5mm 却超全局 4mm 被误回退，回到 40mm 原位反而更差）。
- **解法**：扩大各验证工位容差减少误回退。但注意 6.3 的教训——XL 因"容差同时管触发"反而要收紧。最终各工位分别调（见第七节参数表）。
- **WQ 特例**：WQ 回退残差 13.6/17.0mm（Z 向单目噪声大），容差放宽到 18mm。

### 6.5 服务端去掉"文件名含 xl 自动开旋转"规则
- 原服务端 `effective_rot = rot_comp or ('xl' in name)`，会让 XL（参考名含 xl）**强制开旋转**，导致 XL 关旋转失效。已改为**完全听主控传入的 rot_comp**。

### 6.6 遗留/观察项
- **WF 仍偶发翻转（~1/10）**：关旋转后翻转从高频降到偶发。残余原因推测为"**每轮 WF 纠偏后起始 Z 波动大（0.945~0.980，跨度 35mm）+ 固定下放量**"导致料条触台时机不一致。**治本方向**：改成"按目标绝对高度下放"（不管起始多高都降到同一绝对 Z），消除起始波动。此项待定，未改。

视觉工位参数（`_run_align_onestep` 内）：

| 工位 | rot_comp（旋转补偿） | zero_z | xy_tol_mm | one_step_verify（验证回退） | 放料下放 |

## 十、踩坑与教训

1. **必须区分"PLC等待"与"机器人净耗时"**。PLC 等待每轮波动大，看整轮总时长会误判优化效果。
2. **节拍记录器时钟要用 `monotonic`**（墙钟受 NTP 跳变影响）；并行动作要用"墙钟区间并集"统计，否则各段相加会虚高、掩盖并行收益。v2 保证"并集+间隙≈净耗时"可对账。
3. **GO 的 done 回执 != 底盘物理停稳**。到位后直接伸手会"没到位就伸"，需显式停稳等待（SETTLE_AFTER_GO_S）。
4. **WF/XL 导航途中挂载（边走边挂）会扫掠碰撞**，现场验证后放弃，保持 GO 同步到位再挂载。
5. **跨段并行（提前去弯曲机取料）不可行**：会遮挡弯曲机光栅导致其中断。已放弃。
6. **视觉常驻的收益会被"客户端进程冷启动"吃掉**，必须做到主控进程内直连 socket（方案A）。
7. **常驻服务不能前台跑在终端**（关终端即死、socket 残留致 Connection refused），要用 setsid+nohup 后台守护，并保留主控侧降级兜底。
8. **充电状态下视觉起不来**（GDKBackend 的 POWER 校验），验证/标定前确认拔充电。
9. **关节插值下压(WF2/XL2)会斜向移动致料条翻转**，需用"保持姿态的笛卡尔垂直下放"代替。
10. **视觉旋转补偿(rot_comp)对 WF/XL 是有害的**——其 rotation 读数是测量偏差，补了反而转歪翻转。放料工位应关旋转。
11. **OFFSET 执行有系统性欠程 + 偶发 0mm 漏放**，下放必须做"读 Z 验证 + 补发"闭环，不能开环发一次了事。
12. **`xy_tol` 一参两用**：既是"动作前纠偏触发门限"又是"动作后验证回退阈值"。放宽它减少误回退的同时会降低纠偏触发率（XL 挂挡板的隐藏根因）。调整时务必同时考虑两个作用。

## 十一、迁移到另一台机器人需要做的整理

本套优化策略可迁移到同型号机器人，但须区分"可直接复制"与"必须针对新机器重做"。

### A. 可直接复制的代码文件（逻辑通用）
`all_machin_plc_vision_loop_onestep.py`、`vision_align_server_115.py`、`vision_align_client_115.py`、`run_vision_align_server_115_daemon.sh`、`run_loop_onestep_profile_115.py`/`.sh`、`qjx_profiler_onestep_115.py`、`wf_vertical_place_115.py`。

### B. 必须在新机器重新标定/示教（机器相关，不能直接搬）
- **放料下放 dz**（`wf_vertical_place_dz.json`）：每台机器关节/末端不同，必须 `calibrate --station WF/XL` 重标。
- **视觉参考**（`pick_sl1/pick_wq/pick_xl/place_reference.json`）：相机外参/工装位置不同，必须重新示教。
- **各工位参数**（rot_comp/xy_tol/下放量/zero_z）：现值是 115 现场调出来的，新机按现场重调。
- **关节位姿**（WF1/WF2/XL1/XL2/SL1-3/WQ1-3/FW 等）、**地图点**（GO 1/2/3）：重新示教。
- **SETTLE_AFTER_GO_S**：底盘停稳特性可能不同。

### C. 硬编码要改
- 绝对路径 `/data/wxf0721/runtime/programs/`、socket 路径 `/tmp/vision_align_115.sock`、机器标识 `115`、机器 AID。

### D. 建议上线步骤
1. 复制 A 类文件、改 C 类硬编码；2. 示教 B 类位姿/地图点/视觉参考；3. 标定 dz；4. 先不开常驻跑通基本流程；5. 开常驻 + 带记录器跑，逐工位调容差/下放量/停稳；6. 跑 10+ 轮确认节拍与放料质量。

> **注**：115→29 的实际移植中发现，B/C 之外还有一层"底层软件差异"必须核对（minth done 匹配机制、services 运动准入单槽 vs 双通道、启动握手看门狗、网段/路由到 PLC 等）。详见《G2机器人115节拍优化和29移植经验总结》。

## 十三、后续可继续的方向

1. **WF 偶发翻转治本**：改"按目标绝对高度下放"，消除每轮起始 Z 波动的影响（见 6.6）。
2. **底盘 GO 导航(~30s)** 是当前最大头，但属物理移动时间，软件难压。若要再降需改 PNC 导航参数（加减速/速度上限），风险较高、需重启 PNC，收益在短距离下有限。
3. **WBC 关节(~16s)** 已全局 0.6，再提速换抖动/过冲风险。
4. **停稳 SETTLE_AFTER_GO_S** 若现场长期稳定，可再试更小值。
